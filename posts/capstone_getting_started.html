    The Signup/Login System

    WOW This Code Sucks. Already. I figured out what the problem was—it wasn't that the database was unreachable or anything like that. The database was perfectly reachable, in fact. The problem was that the users table in the database was blank. That's literally the whole thing lol.

    My index.php is running a SELECT * FROM users query, and then a foreach loop on the results, comparing the uname field of each result to the user's chosen username. If they match, an error is thrown; if not, the username and password are inserted into the database (plaintext btw 😭🫶).

    We're gonna ignore the two obvious problems there—that passwords aren't being hashed, and that the foreach loop only needs one non-match in order to try and insert the new user's creds. The problem: because the database was blank, the returned results from the sql query were also just... blank. The foreach loop had nothing to run on, so it wasn't running at all.

    I guess that's a reasonable mistake to make—but yeah, in order to make my signup/login page work, I've just added an admin/admin record to the users table. Now that there's actually something for the query to return, the foreach loop is actually running, and new users can be created. Hell of a fix right there.

    The "potato" room is open to the whole wide internet with no login required, and it's literally just a Websocket broadcast server—a client connects, a javascript prompt() asks you for what you want your username to be, and then whatever you send to that websocket gets broadcasted to EVERY connected client (including the one that sent it lol) and then placed straight into the innerHTML of the div with ID bruh.
