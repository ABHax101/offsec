    Introduction

    Web Hacking is trickier than I remember.

    This week was all about the third section in TryJackMe's Jr. Pentester course, Introduction to Web Hacking. Frankly, it's way longer than I thought, and I may have been a bit overzealous when I assumed I'd finish it in a week. I'm about halfway through at this point, but there's already been a good few learning moments worth documenting. Overall, there was one main theme that kept coming back to bite me: everything is guilty until proven innocent. Random unsuspecting JS file? Not so unsuspecting. That innocent looking favicon? It might be advertising CVEs. That AJAX call in the network tab? Might be a red flag too. I've learned that if it exists on the page, it deserves scrutiny.


    The big realization came early this week, during the "walking an application" room. I was kinda just staring at the page, not really knowing what to do next, but then I saw a mention of "page source" in the guide. I tried viewing the page source and immediately found two flags in the HTML comments.

    It hit even harder when I found another flag purely by accident: I deleted a paywall element using the "inspect element" tool, and wouldn't you know it, there it was. It existed pretty unassumingly on the page, and it was hiding something—why wouldn't it?

    Above all, it made me recognize how important enumeration is. I can't just look at a page, see nothing, and assume it's empty. I need to find everything.

    The "suspicious-by-default" approach paid off multiple times during the module:

    • Directory listings: Found a flag.txt sitting in /assets because I actually checked if such directories were listable. This was another moment where I realized why tools like gobuster should be a default first step.
    • HTML comments: At the very beginning I saw "Page Generated in 0.03572 Seconds using the THM Framework v1.2." I didn't know it at first, but THM Framework v1.2 turned out to be vulnerable.
    • Obfuscated JS: There was a file called flash.min.js that seemed like a page dependency; however, while I could verify that the jQuery and Bootstrap files were legit, I couldn't figure out what "flash" was supposed to be. I used the debugger to deobfuscate it, and adding a breakpoint revealed a flag being flashed on screen for a split second. Blew my mind.
    • AJAX calls: The contact form made a POST request to /contact-msg which seemed pretty normal. Didn't question it until I saw the word "AJAX" in the activity. Wouldn't you know it, the AJAX flag was hiding there.

    All of these would have been super easy to ignore if I was just clicking through the app as I'd been doing. The lesson is clear:

    Enumerate everything; trust nothing.

    This week's biggest struggle was more conceptual than technical. The "logic flaw" section in the Authentication Bypass room left me genuinely confused for a solid chunk of time.

    It was like this -

    There's a password reset function, into which you pass an email from the URL query string (/?email=anybody@prdox.me). But later in the PHP code, it references $_REQUEST; if you've used PHP before, you might know that if a key exists in the URL query string and in $_REQUEST, $_REQUEST takes priority.

    I understood this concept once it was explained, but I didn't understand how I was even supposed to figure that out in the first place. I didn't even know it was a PHP app, let alone that it may have been using $_REQUEST instead of $_GET and $_POST.

    Eventually I figured out that the assumption is that the app simply has bad code. It makes sense that many PHP apps might use $_REQUEST because it's just convenient (albeit a common bad practice). It's not something I'm just supposed to know upfront—it's something I'm supposed to test for by giving the app some nonsense and seeing what it does with it.

    The struggle taught me something important: hacking isn't a separate discipline from computing, and it'll only make sense when I treat it as an extension of what I already know about computing. I can't go on treating it as something isolated; everything that I've learnt about computers—from SEC-110, from writing my own code, from that one networking course, etc—matters in some way in the hacking world as well.

    Not everything will announce itself, and learning to read between the lines is part of the work.
