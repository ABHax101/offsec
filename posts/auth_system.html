    Back to the login form now: what happens when we try registering users with weird usernames? Like <script>alert(1337)</script>? Pretty sure our username is gonna be embedded somewhere or the other, so I bet this can cause some weird BS.

    Heh, yeah, like that:

    That's what landing.php looks like, by the way. The snippet of code up at the top there is coming from our blacklist.php which we'll look at in a bit. The relevant part is here:

    if ((list.includes(fingerprint)) // where `list` is an array of blacklisted client fingerprints
        && (![/* whitelisted usernames */].includes("<?=$_SESSION['Username']?>"))) {
            location.href='about:blank'
        }

    landing.php does a require("./blacklist.php") in there somewhere, so the javascript in blacklist.php gets dropped into this file as a <script> element at the top. It's looking like when our <script>alert(1337)</script> gets dropped into the JS there, it's seeing the </script> in the username and interpreting it as the actual end of the script tag itself, so the rest of the file just gets dumped into the DOM.

    That's actually some really interesting behavior—it allows for some really weird injections lol. With a simple </script> in the username, we can inject straight HTML into the page. But that's only on our own page... Not too sure how an attacker would actually use this. It's kinda like a self-XSS scenario, except I can't really see any reasons why that'd be useful in an application like this.
